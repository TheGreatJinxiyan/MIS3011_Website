# ResumeCube 简历魔方 · 前端交付（设计稿第 4、5 页）

> MIS3011 Group Project · 依据《ResumeCube_UIUX设计需求说明书_2.0》§6（积木库 / 新增经历 / 普通分析 / 深入分析）与《ResumeCube 简历魔方 · 产品视觉设计》**第 4 页「新建积木」、第 5 页「深入分析」** 实现。
>
> **English summary:** A dependency-free front end for the two assigned screens of the *Cube Library* module: **New Cube** (P4) and **Deep Analysis** (P5). It parses whatever material the user actually uploads (TXT / PDF / DOCX / image-OCR), sends the text to the Dify model, and renders the returned structured JSON into an editable cube and a multi-round interview. No design screenshots are used as UI.

## 3. 快速开始

### 方式 A：本地一键跑通（推荐，AI 实时生成可用）

1. 装好 Python 3（无需任何 pip 包；Windows 自带 `py` 启动器即可）。
2. 双击 `start.bat`（内部优先 `py proxy.py`，也兼容 `python proxy.py`）。**服务已在运行时会自动跳过启动、只打开页面**，不会报「端口被占用」。
3. 浏览器打开 `http://127.0.0.1:8787/`，顶栏出现 **绿点「MCP · 本地代理已连接」** 即表示 AI 通道就绪。
4. 上传材料（或点「填入示例材料」）→ 点「生成积木」→ 白色加载方框显示进度 → 约 30–120 秒后出现可编辑的分析结果预览 → 「保存积木」。
5. 点「继续深入分析 →」进入 P5，模型逐轮追问；每轮回答进入草稿，点「确认并更新积木」才合并进积木。

> 顶栏若是**红点**「MCP 直连（需启动 proxy.py）」，说明页面是双击 `index.html` 以 `file://` 打开的，浏览器会被 CORS 拦住。请改用 `proxy.py` 托管的网址。

### 方式 B：GitHub Pages / 纯静态托管

在页面右上角「设置」里填入 **Dify 应用 API 密钥（`app-` 开头）**，通道选 `/v1`。`/v1/*` 已实测返回 `Access-Control-Allow-Origin`，浏览器可直连，无需本地代理。
密钥路径：Dify 应用 → 访问 API → API 密钥。

> 当前提供的 `sk-12af…` 是 **MCP Server 令牌**，不是 `app-` 密钥，直接用于 `/v1` 会返回 401。

### 方式 C：离线演示与验收入口

| URL | 用途 |
|---|---|
| `http://127.0.0.1:8787/?demo=1` | 无需联网，直接显示 P5 设计稿示例对话（**演示数据，不调用模型**） |
| `http://127.0.0.1:8787/?loading=1` | 直接显示加载态，验收**白色实底方框**是否遮挡干净 |
| `http://127.0.0.1:8787/?view=deep` | 恢复本机上次保存的深入分析进度 |

### 真实生成链路（不是静态图）

```
上传文件 / 粘贴文字说明
  → 前端提取纯文字（TXT 直读 / PDF pdf.js / DOCX mammoth / 图片 Tesseract.js 中文 OCR）
  → 拼装 query = 任务规则 + 固化的输出 JSON 契约 + 时间 + 用户文字 + 材料正文
  → 调用 Dify MCP 工具「小组作业」(tools/call)
  → 剥离 <think> 推理块 → 解析结构化 JSON → 归一化
  → P4 渲染可编辑的分析结果预览（字段 / 标签 / 证据 / 待确认推测）
  → 用户逐项确认并「保存积木」（localStorage）
  → P5 每轮：把积木 + 已有问答 + 最新回答再发给模型 → 得到下一个单问题与已挖维度
  → 回答只进草稿；「确认并更新积木」才合并（原文保留，不覆盖）
```

**可信度落点（说明书 §12）**：请求里明令禁止编造公司、职位、项目、数字、成果、技能；无依据的推测单独放进 `unconfirmed` 并在预览区用橙色框标出「没有被写进积木」；深入分析里用户说「记不清了」就换方向，不诱导编数字；每轮回答与进度自动保存，可暂停后再继续。

## 5. 输出契约（固化在请求 query 里，不依赖 Dify 侧 system prompt 版本）

**普通分析 `CUBE_SCHEMA`**

```json
{
  "status": "ok | insufficient_material",
  "status_message": "",
  "cube": {
    "title": "", "org": "", "role": "", "type": "课程作业|实习|项目|竞赛|科研|社团/校园|兼职|其他",
    "start": "", "end": "", "summary": "",
    "bullets": [""], "actions": [""], "results": [""],
    "tags": { "hard": [], "soft": [], "domain": [], "workstyle": [], "outcome": [] },
    "keywords": []
  },
  "evidence": [{ "field": "", "quote": "" }],
  "unconfirmed": [{ "field": "", "value": "", "reason": "" }],
  "suggested_questions": [""]
}
```

**深入分析 `DEEP_SCHEMA`**

```json
{
  "question": "下一轮唯一的那个具体问题",
  "round": 4, "total": 6,
  "note": "对用户最新回答的一句反馈",
  "confirmed_draft": "可写入积木草稿的一句事实",
  "dug": [{ "key": "goal|duty|action|result|difficulty|capability", "label": "", "value": "", "from": "" }],
  "dimensions": { "目标": "", "职责": "", "行动": "", "结果": "", "困难": "", "能力沉淀": "" },
  "progress": 4,
  "ready_to_summarize": false
}
```

前端做了兜底：`normalizeCube()` 兼容扁平 / 字符串字段，`tags` 缺类补空数组；深入分析轮次由前端控制（不信任模型自报的 `round`），避免进度跳乱。

## 6. 接口实测结论（2026-11-13，逐条验证）

| 项 | 结果 |
|---|---|
| `https://api.dify.ai/v1/chat-messages` + `sk-12af…` | **HTTP 401** `Resource access token is invalid`。该 `sk-` 不是 Dify 应用 API 密钥（`app-` 开头） |
| `https://api.dify.ai/v1/*` 的 CORS | **支持**，OPTIONS/POST 均回显 `Access-Control-Allow-Origin`，浏览器可直连 |
| `https://api.dify.ai/mcp/server/nMpZfw4ZeCtHxFAf/mcp` + `sk-12af…` | **可用**。`initialize` 返回 `Dify 1.19.0`；`tools/list` 返回工具 **「小组作业」**，入参仅 `{query: string}` |
| MCP 端点 CORS | **不支持**，且带 `X-Frame-Options: DENY` → 浏览器 / iframe 都直连不了，这是必须配 `proxy.py` 的原因 |
| 内嵌 URL `https://udify.app/chat/jweJ7tiGyBhkuUVU` | 带 XFO DENY，**不能 iframe**。改用 Dify 官方 `embed.min.js` 气泡（token = 该 chat id，默认关闭可开启）+「打开 Dify 对话」新窗口按钮 |
| 模型 | **推理模型**，正文前固定带 `<think>` 块（prompt 明令禁止也无效）。前端 `parseModelJson()` 先剥离 think / Markdown 代码块再解析；失败自动用更严格指令重试一次 |

### 本次两条链路实测（2026-11-13，用页面真实契约并行调用）

| 链路 | 耗时 | 模型正文 | 返回并被前端消费 |
|---|---|---|---|
| **普通分析** | 27.0 s | 11,580 字符（含 think） | `status=ok`、标题「MIS3011 用户留存分析」、类型课程作业、组织/角色、时间、摘要、**3 条 bullet / 6 条行动 / 4 条结果**、**5 类标签齐全**、3 条 `evidence`、1 条 `unconfirmed` → `normalizeCube()` 通过 |
| **深入分析** | 30.6 s | 9,156 字符（含 think） | 下一问「清洗数据时，你具体处理了哪些数据质量问题？」、反馈 `note`、可写入草稿、**4 个 `dug`**、**6 个 `dimensions` 键齐全**、`ready_to_summarize=false` → `deepStep()` 通过 |

> 两条并行总耗时 30.7 秒。同一应用此前完整 JD 链路实测曾达 82.5 秒，耗时取决于推理长度；**性能瓶颈在 Dify 侧推理模型**，换非推理模型或关闭思考模式可压到 10–20 秒、响应体缩小约 40 倍，这需要项目管理者在 Dify 应用侧调整。

**页面内置三条 AI 通道，自动按优先级降级：**

| 通道 | 凭证 | 适用 |
|---|---|---|
| `/v1` 应用 API | `app-xxx` | GitHub Pages / 任意静态托管，CORS 已验证，最省事 |
| MCP + 本地代理 | `sk-12af…`（已写入 HTML） | 本机 `proxy.py`，当前唯一开箱即用的实时生成通道 |
| Dify 官方气泡 | 无需密钥 | 备用对话入口，默认关闭，结果不回写页面 |
